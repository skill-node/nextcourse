## 课程大纲

> 授课形态说明：模块三的 slide 只做「场景讲解」，讲完后切换到电脑现场演示实操，
> 因此本课程 slide 不含工具操作截图。slide 部分约 55–60 分钟，现场演示约 30 分钟。
>
> 复用性约束：模块一、模块二为通用骨架，**不得渗入保险行业案例**；
> 更换受众人群时只重写模块三的案例页（未来命名 workbuddy-<行业>）。

### 封面与概览（2 张）
- 封面页：标题 + 核心价值主张「让 AI 替你动手办事」
- 课程概览：五条学习成果 + 四个模块地图 + 今天会现场演示的说明

### 模块一：认清你在用的是什么（6 张）
- 模块封面
- Concept：三层关系——大模型是发动机、智能体是整车、WorkBuddy 是你买的那辆车
- Hook→Concept：「它聊着聊着就忘了前面说的」→ 上下文窗口与 token（先摆现象，再给概念）
- Hook→Concept：「为什么网页版 AI 帮不了我把消息发出去」→ API / 工具调用 = 智能体能"动手"
- Concept：你打的字去哪了——数据流向（为后面的合规判断打地基，不做说教）
- Key Takeaway：聊天框只能动嘴，智能体才能动手

### 模块二：把话说对——提示词五要素（7 张）
- 模块封面
- Concept：五要素公式 = 角色 + 对象 + 目标 + 约束 + 格式
- Demo：before / after 对比 ①——客户异议处理话术
- Demo：before / after 对比 ②——保险条款白话翻译
- Demo：before / after 对比 ③——宣传文案改写
- Practice：五个低级错误自检（没说对象是谁 / 没给约束 / 一次问太多 / 不给格式 / 不追问改稿）
- Key Takeaway：AI 答得差，通常不是它笨，是你没把话说完整

### 模块三：保险人的五个实战场景（10 张）
- 模块封面
- 工具全景（1 张，本模块唯一的工具页，不写网址）：
  - 分两组呈现，避免受众混淆——
  - `日常办公型`（今天就能上手）：WorkBuddy（腾讯）、千问办公（阿里）
  - `专业开发型`（了解 agent 的光谱，非今天重点）：OpenClaw（开源社区）、Claude Code（Anthropic）、Codex（OpenAI）
  - 建议组件：table-compare，列为 产品 / 厂商 / 一句话定位 / 适用人群
- 案例页按「agent 含量」由弱到强排列，每页暗线都是一句话：这事为什么聊天框做不了
  - 案例 ①：保险条款白话解读 —— 聊天框要手动贴，智能体可直接读文档 / 挂知识库、可复用
  - 案例 ②：客户跟进与生日节日触达 —— 聊天框只能一条条问，智能体可定时触发 + 批量 + 写日程
  - 案例 ③：建议书 / 方案对比初稿 —— 聊天框只能出文字，智能体可读多份材料并输出成品文档
  - 案例 ④（占 2 张）：三份实战素材 → 一张宣传长图 —— 聊天框文案能出、图要另开工具，智能体图文一次出成品
    - 第 1 张：素材等式——住院结算单 + 费用明细 + 报销政策图 = 可发的宣传长图
    - 第 2 张：同一需求的两种提示词原文对照，落点是「多图任务必须给每张图派活」
  - 案例 ⑤（压轴，占 2 张）：杂乱的医疗保险发票 → Excel 明细清单
    - 第 1 张：痛点与不可行——多张照片、格式不一、手工录入耗时，聊天框基本做不了
    - 第 2 张：智能体怎么做——多图输入 → 结构化提取 → 落成文件；
      **页内必须内嵌 callout warning**：上传前遮挡身份证号与诊断细节，只留项目与金额
- Key Takeaway：找出你手上"最费时又最机械"的那件事，那就是切入点

### 模块四：人机分工与销售合规（2 张）
- 客户信息分级判断：什么绝对不能出、什么可在企业版工具内处理、上传前的最小化动作
- 销售宣传红线：不承诺收益、不贬低同业、AI 不知道你司产品报备口径；
  一句话原则——**AI 出初稿，人负责签字**
