# 内容开发 — 访谈、案例、数据包与排期

> `nextcourse-delivery` Phase 7 的参考。课程落不了地，缺的从来不是 PPT，
> 是**案例、数据包和讲师**。

## SME 访谈提纲

每位业务专家 45–60 分钟。目标是**逼出具体案例和隐性判断标准**，不是收集方法论
——方法论你自己就能写，只有他知道真实场景里事情是怎么砸的。

### 开场（2 分钟）

「今天不用您准备内容，我问，您讲故事就行。讲得越具体越好，最好带上时间地点人物。」

### 主问题（按顺序问，不要跳）

1. **做得好的人和做得差的人，差别最先出现在哪一步？**
   （定位教学重点。答案往往不是你以为的那一步。）
2. **最近一次做砸的例子是什么？当时是怎么判断的？**
   （最好的案例素材永远来自失败。）
3. **新人最常犯的三个错误？**
   （直接转成课堂的判断题与「常见卡点」。）
4. **您自己的判断标准是什么？**
   （逼出隐性知识。追问「如果换成 X 情况您还这么判断吗」。）
5. **有没有一份真实材料可以脱敏后当课堂案例？**
   （拿到材料比拿到观点值钱十倍。）

### 收尾

「我整理完会给您看一遍，确认没写歪、也没泄露不该有的信息。」
——这句话决定了他下次还愿不愿意接受访谈。

### 记录要求

录音（征得同意）+ 当场记关键词。访谈纪要 24 小时内整理，
每条案例转成**案例卡**，超过 48 小时细节就丢光了。

## 案例卡结构

课堂上真正好用的案例长这样，缺哪一栏都会在授课时卡壳：

```
标题    ：一句话，含冲突（「客户当场翻脸的那份建议书」）
背景    ：2–3 句，交代角色、时间点、约束条件
材料    ：学员实际会看到的东西（表格 / 截图 / 对话记录，已脱敏）
任务    ：学员要做什么判断或产出
参考答案：不是唯一答案，是「达标答案 + 关键判断点」
坑      ：学员大概率会踩的 1–2 个错误，讲师点评时对着打
```

**每模块 2–3 个案例**：一个用于示范（讲师带着走），一个用于练习（学员做），
一个备用（现场节奏快时加练，或替换掉讲不通的那个）。

## 练习数据包与脱敏

### 脱敏是硬规则，没有例外

真实客户材料**一律不得直接进入课件与数据包**。必须替换的字段：

| 字段 | 处理 |
|---|---|
| 姓名 | 换成虚构姓名，同一份材料内保持一致 |
| 手机号 / 邮箱 / 地址 | 换成明显虚构值（138-0000-0000） |
| 单号 / 保单号 / 合同号 | 保留位数与格式，数字全换 |
| 金额 | **不要只改末位**——按比例整体缩放，避免反推 |
| 公司名 / 机构名 | 换成「A 公司」或虚构名，不用真实同行 |
| 截图里的头像与水印 | 涂掉，注意侧边栏和通知栏也会泄露信息 |

替换后**必须让 SME 或委托方确认一遍**：他们比你更知道什么组合能被认出来。

### 数据包组织

```
package/exercises/
  m2-prompt-rewrite/
    README.md        这份给哪个模块用、学员要做什么、达标答案长什么样
    input/           学员拿到的原始材料
    sample-output/   达标产出样例（讲师用，不发给学员）
```

命名 `m<模块号>-<练习名>`，一个练习一个目录。

## 排期表

没有责任人和日期的开发计划等于没写。最少这五个里程碑：

| 里程碑 | 交付物 | 责任人 | 日期 |
|---|---|---|---|
| SME 访谈完成 | 访谈纪要 × N | | |
| 案例库定稿 | 案例卡 × N（含脱敏确认） | | |
| 数据包脱敏完成 | `exercises/` 全套 | | |
| 课件与手册定稿 | `deck.html` + `package/` | | |
| 试讲与修订 | 修订清单 + 定稿版 | | |

### 经验值

- **试讲不可省**。第一次讲一定超时，超的通常是 20–30%；
- 案例定稿到开课至少留 1 周，中间会有人反悔说某个案例不能用；
- 数据包脱敏比想象中慢——一份含 20 张截图的材料要 2–3 小时。
