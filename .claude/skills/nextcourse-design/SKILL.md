# nextcourse-design — 课程设计

对话式地引导用户完成**规格诊断 → 定位 → 目标体系 → 整体设计 → 模块架构**，产出 `courses/<name>/course.meta.md`，为 `nextcourse-slides` 提供完整输入。M / L 档另外产出 `courses/<name>/course.blueprint.md`（设计层真相）。

## 开工前：确认引擎在

```bash
nextcourse doctor
```

没这个命令就装：`npm i -g nextcourse`（或每次用 `npx -y nextcourse`）。
doctor 会报出**当前工作目录** —— 课程就落在那个目录的 `courses/<name>/` 下。如果用户想放别处，先 `cd` 过去再开始。

## 对话语言

**跟随用户的语言。** 本文档的提示词是中文写的，但那只是本文档的语言，不是对话的语言：用户用英文提问就全程用英文回，用其他语言同理。产出的文件也用同一种语言写 —— 字段名（`title` / `outcomes` / `do` / `bloom` / `success` 等）保持英文不变，字段的值跟随用户语言。课程内容本身的语言由用户决定（他要给谁讲课），不确定时问一句，不要默认中文。

## 工作流总览

```
Phase 0: 规格与需求诊断 → 定档位、画像、痛点北极星、范围边界
Phase 1: 定位          → 受众、情境、价值主张
Phase 2: 目标体系      → Bloom 学习成果（M/L 档追加柯氏 L1+L2）
Phase 3: 课程整体设计   → 形态、时长、分组、一日旅程          【M / L 档】
Phase 4: 模块架构      → 模块 = 主题 + 时长 + 活动 + 产出物 + 覆盖成果 + 页数
           ↓
     写 course.meta.md（+ M/L 档写 course.blueprint.md 一~五节）
           ↓
     nextcourse check <name>  → 教学设计闭环校验
           ↓
     提示用户进入 nextcourse-slides <name>
```

**在每个 Phase 内，先用 1-2 个问题引导用户，再给出建议，用户确认后才推进到下一阶段。不要一次输出所有内容让用户被动接受。**

如果用户明确要复用其他课程，仍然先完成本课受众、成果和模块设计，再检查工作区已有的
`course.exports.json`。输出一张“本课成果 → 候选公开单元 → 本地补充”的复用地图；
没有显式 export 的内容不能当作共享接口，不根据题目相似就复制文件。普通课程不创建 compose 文件。

## Phase 0：规格与需求诊断

**这是全流程第一个问题，先定档位，因为它决定后面要问多少东西。**

**问题 1：** 这门课多长、什么场合？

根据回答定档（拿不准就把三档念给用户选）：

| 档位 | 适用 | 走哪些 Phase | 产出 |
|---|---|---|---|
| **S · 分享课**（默认） | 30–90 min，公开课 / 内部分享 / 主题演讲 | 0（精简）· 1 · 2 · 4 | `course.meta.md` |
| **M · 内训课** | 半天 ~ 1 天，企业内训 | 0 · 1 · 2 · 3 · 4 全套 | + `course.blueprint.md` |
| **L · 培训项目** | 训练营 / 体系化项目 / 需交付 ROI | 同 M，另加 `nextcourse-delivery` | + 完整蓝图 |

> **S 档是轻量流程，不要给它加负担。** S 档在 Phase 0 只问上面这一个问题，
> 确认「30-90 分钟的分享」之后直接进 Phase 1，下面 2–5 题全部跳过。
> 只有 M / L 档才继续问。

**问题 2（M/L）：** 学员现在是什么水平？——是「从零教」还是「给老手换工具」？

> 这一问决定整门课的起点。老手最烦从头讲概念，新手最怕直接上手。

**问题 3（M/L）：** 不培训的话，现在业务上会继续发生什么损失？（**业务痛点北极星**）

> 一句话，具体到能被业务负责人认领。这句话后面要撑起柯氏 L3/L4 的讨论。

**问题 4（M/L）：** 交付形态？（线下集中 / 线上直播 / 混合；一次还是分几次；班级规模与分组）

**问题 5（M/L）：** **本期明确不做什么？**

> 这一问最容易被跳过，但它是专业度的分水岭——现在的课程之所以越做越胖，
> 就是因为只问「要什么」不问「不要什么」。至少逼出 2 条，并各写一句理由。
> 例：「获客与线索挖掘本期不做——那是另一套方法论，一天讲不完，会挤掉实操时间」。

### Phase 0 产出（M/L 档，写进蓝图第一节）

```
档位      : M · 内训课
交付形态  : 1 天线下集中，20–30 人，4–5 人一组
总时长    : 1 天（有效 6.5h）
学员现有水平 : ...
业务痛点（北极星）: ...
委托方最在意的结果 : ...
本期不做  : ① ... （理由）  ② ... （理由）
```

确认后进入 Phase 1。

## Phase 1：课程定位

### 引导对话（依次问，不要一次全问）

**问题 1：** 这门课程是给谁上的？（角色 + 经验水平 + 场景）

> 例："公司内部培训，面向刚入职 3 个月的销售人员" / "付费在线课，面向想转行数据分析的 28-35 岁职场人"
> （M/L 档 Phase 0 已经问过学员水平，这里不要重复问，直接复述确认即可。）

**问题 2：** 学员上完课之后，希望他们能做到一件具体的事是什么？

> 用"他们能够…"造句，越具体越好

### 根据用户回答，产出：

```
受众画像  : [1 句话描述]
核心情境  : [学员在什么场景下用这门课学到的东西]
价值主张  : [为什么他们要学这门课而不是别的]
```

让用户确认或修改后进入 Phase 2。

---

## Phase 2：目标体系

起草 3–5 条学习成果，用 Bloom 动词，每条可测量。

**动词表、字段定义（`id` / `do` / `bloom` / `success` / `module` / `evidence`）、质量闸门、引导话术，见 `references/bloom.md` —— 要动笔起草成果时读它。**

M / L 档还要定评估层级：**默认只设计 L1 + L2，不问、不等，直接给**，然后就 L3/L4 问一句基线数据归属。**完整规则见 `references/kirkpatrick.md`。**

确认后进入 Phase 3（M/L）或直接进 Phase 4（S）。

---

## Phase 3：课程整体设计【M / L 档】

**S 档跳过这一节。**

**问：** 一天怎么排？——先给建议再让用户改，别让用户从空白开始。

要定下来的四件事：

| 项 | 说明 |
|---|---|
| 教学形态 | 讲授 / 示范 / 动手练习 / 小组共创 / 互评 的配比 |
| 分组方式 | 几人一组、按什么混编、要不要设组长 |
| 一日旅程 | 时间轴：开场 → 各模块 → 茶歇 → 收尾，落到具体钟点 |
| 认知负荷节奏 | **每 90 分钟必须切换一次形态**；午后第一段必须是动手环节，不能是纯讲授 |

时间轴示例（写进蓝图第四节）：

| 时间 | 环节 | 形态 | 时长 |
|---|---|---|---|
| 09:00–09:20 | 开场与破冰 | 讲授 + 互动 | 20 min |
| 09:20–10:30 | 模块 1 | 讲授 + 案例讨论 | 70 min |
| 10:30–10:45 | 茶歇 | — | 15 min |

> 各模块时长之和 + 开场收尾休息 必须等于声明的总时长，
> 差太多 `nextcourse check` 会报警。**别把一天排满 8 个模块**——
> 成年人一天能真正吸收的模块数是 3–5 个。

---

## Phase 4：模块架构

### 原则
- 每个模块聚焦**一个核心主题**（学员离开时能说出这一句话）
- S 档：2-4 个模块，每模块 5-8 张幻灯片，总页数 15-30 张（60-90 分钟）
- M/L 档：3-5 个模块，每模块必须有**时长**和**产出物**
- 开头必须有：封面（1张）+ 课程概览（1张）
- 每个模块必须有：模块封面（1张）+ 内容页 + 模块总结或过渡（1张）
- 结尾必须有：学习路径 / 下一步（1张）+ 致谢/结束（1张）

### Merrill 第一原理（每模块内部结构参考）

```
Hook     → 为什么学员要在乎这件事？（问题 / 现实冲击）
Concept  → 核心知识点是什么？
Demo     → 真实案例 / 流程演示
Practice → 学员能练习什么？
Takeaway → 这个模块最重要的一句话是什么？
```

### 引导对话

**问：** 这门课的内容可以分成几个大块？每一块核心解决什么问题？

**M / L 档每个模块必须补齐这一行**（写进蓝图第五节的模块清单表，`check` 直接解析它）：

| # | 模块 | 时长 | 教学活动 | 产出物 | 覆盖成果 |
|---|---|---|---|---|---|
| 1 | 认清工具边界 | 70 min | 讲授 + 对比讨论 | 工具选择速查卡 | LO1 |
| 2 | 把话说对 | 90 min | 示范 + 动手改写 | 个人提示词模板 3 条 | LO2 |
| 3 | 实战场景 | 90 min | 小组共创 + 互评 | 个人作战包 | LO3、LO4 |

> **产出物是这一步最关键的升级。** 每个模块必须有一件学员能带走的东西
> ——一张速查卡、一份填好的清单、一个作战包。「学完有什么带走」是内训能不能落地的
> 分水岭，比多讲两个知识点重要得多。想不出产出物的模块，八成是纯知识灌输，该重新设计。

模块定完，**回到 Phase 2 把每条 outcome 的 `module` 字段填上**——这时候才填得准。

S 档仍然按老样子给页面级拆分即可：

```
模块一：XXX（约 X 张）
  解决问题：...
  核心页面类型：Hook → Concept → Demo → Takeaway
```

如果用户对某个模块有具体内容要求（某张页面要加什么），在这一步记录下来。

## 题材域适配（贯穿各 Phase 使用）

不同题材的教学形态差异很大。识别课程所属题材后，按题材调整引导重点、模块结构和 theme 推荐：

```bash
nextcourse docs domains
```

那张表给出每个题材的教学形态重点、Practice 形式、推荐配色，以及做课件时的组件倾向。**推荐值都可以被用户覆盖** —— 用户明确说了要什么就按用户的来。

## 输出

文件模板（S 档 meta / M-L 档 frontmatter 追加字段 / 蓝图一~五节的分工），见 `references/output-templates.md` —— 要动笔写文件时读它。

课程目录还不存在就先建：

```bash
nextcourse new <name>              # S 档
nextcourse new <name> --scale M    # M / L 档，顺带把蓝图模板拷进去
```

## 收尾提示

文件写入完成后，**M / L 档先跑一次校验**：

```bash
nextcourse check <name>
```

把报告里的 error 修掉再交给用户（warning 逐条念给用户判断，别自作主张改）。

然后告知用户：

```
S 档：
课程大纲已保存到 courses/<name>/course.meta.md
下一步：让我用 nextcourse-slides 做幻灯片

M / L 档：
设计蓝图  courses/<name>/course.blueprint.md   （一~五节已完成）
构建契约  courses/<name>/course.meta.md
对齐矩阵  courses/<name>/package/7_alignment.md （check 自动生成）

下一步二选一：
  nextcourse-slides <name>      直接开始做幻灯片
  nextcourse-delivery <name>    先补评估方案与交付包
```
