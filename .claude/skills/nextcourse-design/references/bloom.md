# 学习成果的写法（Bloom）

Phase 2 起草成果时读这一份。

## 动词表

| 层次 | 关键动词 |
|---|---|
| 记住 | 说出、列举、识别、定义 |
| 理解 | 解释、总结、区分、举例 |
| 应用 | 使用、执行、操作、完成、配置 |
| 分析 | 分解、对比、诊断、识别原因、判断 |
| 评估 | 评价、选择、验证、论证 |
| 创造 | 设计、构建、规划、开发、生成 |

## 原则

- 3–5 条，不要超过 5 条（宁缺毋滥）
- 每条必须**可测量** —— 能写出怎样的考题或实操任务
- 动词要多样化，至少覆盖 3 个 Bloom 层次

**质量闸门**：若成果大多停留在 记住 / 理解 层，提醒用户"课程可能太浅"，建议至少 1 条达到 apply 及以上。

**题材惯性**：领导力 / 合规类成果多落在 analyze / evaluate 层（判断与决策），技术类多落在 apply / create 层（操作与搭建）。起草的分布与题材惯性不符时，向用户确认是否有意为之 —— 是确认，不是纠正。完整题材表跑 `nextcourse docs domains`。

## 字段

| 字段 | 含义 | 档位 |
|---|---|---|
| `id` | `LO1` `LO2`…，后面所有交叉引用都用它 | S 可省，M/L 必填 |
| `do` | 动词开头的可观察行为 | 全部 |
| `bloom` | 所属 Bloom 层级 | 全部 |
| `success` | 成功标准（怎样算达成） | 全部 |
| `module` | 在**哪个模块**教（Phase 4 定完模块后回填） | M/L 必填 |
| `evidence` | 用**什么证据**判定达成（Phase 2 就要想清楚） | M/L 必填 |

```yaml
outcomes:
  - id: LO2
    do: "使用 X 完成 Y 任务"
    bloom: apply
    success: "15 分钟内独立产出 Y，并通过检查清单验收"
    module: 3
    evidence: "结营实操考核 · 作战包 A 项"
```

> `module` + `evidence` 是逆向设计的燃料：有了它们，「成果 × 模块 × 活动 × 评估」四列矩阵才能自动生成和校验，`nextcourse check` 才拦得住「教了但不测」和「测了但没教」。
>
> **别等到最后补** —— `evidence` 想不出来，通常说明这条成果根本不可测，该重写。

## 引导话术

你希望学员在以下 3 个能力层次上各有什么收获？（可以只回答你觉得重要的）

- 他们需要**知道 / 理解**什么？
- 他们需要能**做到**什么？
- 他们能**创造 / 决策**什么？
