# /course-delivery — NextCourse 交付层设计 Skill

## 触发方式

```
/course-delivery <课程名>
```

**前置条件**：`courses/<name>/course.blueprint.md` 已有一~五节（`/course-design` 产出），
且 `course.meta.md` 的 `scale` 是 `M` 或 `L`。没有就先跑 `/course-design`。

本 skill 补齐蓝图的**六~十一节**，然后生成企业内训真正要交的那一包东西：
讲师手册、学员手册、评估方案、考核量规、教学设计、内容开发计划、行动承诺书。

## 对话语言

跟随用户的语言，与 `/course-design` 一致。字段名与文件名保持英文，内容跟随用户语言。

---

## 第一步：读现状，只补缺的

**不要从头问一遍。** 先读这三样，再决定问什么：

```bash
cat courses/<name>/course.meta.md          # 档位、时长、班级规模、outcomes（含 evidence）
cat courses/<name>/course.blueprint.md     # 一~五节已经定了什么，六节之后有没有内容
nextcourse check <name>                    # 闭环有没有洞
```

然后向用户复述你读到的规格（1–3 行），并**只针对缺失的 Phase 提问**：

| 蓝图已有 | 动作 |
|---|---|
| 只有一~五节（`/course-design` 刚做完） | 从 Phase 5 顺着做到 Phase 8 |
| 已有六节、缺七节 | 直接进 Phase 6，别重问教学手法 |
| 用户手写了完整蓝图，只想要交付包 | 全部 Phase 跳过，直接进「生成交付包」 |

用户已经有手写蓝图但章节标题不一样时，按内容认，不要求他改标题；
但**第五节的模块清单表列名必须是** `# / 模块 / 时长 / 教学活动 / 产出物 / 覆盖成果`
——`nextcourse check` 和 `nextcourse package` 都解析这张表。

**在每个 Phase 内，先给方案再让用户改，别让用户从空白开始。** 你已经知道模块、时长、
班级规模和每条成果的判定证据，这些足够你起草了。

---

## Phase 5：教学方法与互动设计【M / L】

**目标**：把每个模块的「教学活动」从一个词（如「小组共创」）变成可执行的活动指令。

先问一个问题：

> 「这批学员更吃哪一套——先看示范再动手，还是先撞墙再讲原理？」

然后按题材域和班级规模推荐手法组合，逐模块给出：
**活动名 / 分组形态 / 时间盒 / 交付物 / 讲师站位**。

手法库、按题材域 × 班级规模的选型表、时间盒的经验值，见
`references/facilitation.md` —— 需要选手法时再读它，不要一上来就全读。

**硬规则（写进蓝图，不许绕过）：**
- 每 90 分钟必须切换一次形态；
- 午后第一段不得是纯讲授；
- 每个模块至少一次人均发言机会 ≥ 1 次的互动；
- 产出物当场交，不留课后。

写入蓝图 `## 六、教学方法与互动设计`。

---

## Phase 6：评估方案【M / L】

**默认直接给 L1 + L2，不问、不等。** 这是效率决策，不是偷工减料：
L3/L4 的成本不在课程设计侧，而在训前基线采集、跨部门数据口径和 30/60/90 天追踪，
没有业务方配合根本跑不动。

### 6.1 直接产出（不问用户）

1. **L1 反应问卷**：6 道 1–5 分题 + 3 道开放题。题目要能指导改课，
   「课程内容与我的实际工作直接相关」比「您对本次培训是否满意」有用得多；
2. **L2 实操考核**：考核任务**直接取自每条 outcome 的 `evidence` 字段**，
   不要另起炉灶——evidence 就是当初说好的判定证据；
3. **考核量规**：每条 outcome 一个维度，四级（优秀 / 达标 / 待改进 / 未达标），
   每级都写成**可观察的行为**。写「较好」「一般」「有待提高」的量规等于没有量规。

题库、指标写法与量规措辞见 `references/kirkpatrick.md`。

### 6.2 然后问一句（只问这一次）

> 「这门课要不要向业务负责人证明业务结果？要的话我加 L3 行为追踪 / L4 业务指标，
> 但需要你先确认：**基线数据由谁提供、口径是什么**。」

- **说要** → 展开 L3/L4。每个指标必须写明：指标定义、统计周期、剔除规则、
  **基线责任人（姓名 + 部门）**、追踪节奏。需要基线才能定值的目标值后面标 `*`，
  不许拍脑袋写绝对值。
- **说不要** → 蓝图里写明「**本课程评估范围到 L2**」。写明范围本身就是专业度，
  比硬凑四级表格却全是空指标强得多。

写入蓝图 `## 七、评估方案`。

---

## Phase 7：内容开发计划【M / L】

课程落不了地，缺的从来不是 PPT，是**案例、数据包和讲师**。这一节要写清楚
「谁在什么时候交什么」，没有责任人和日期的开发计划等于没写。

产出四块：

1. **SME 访谈提纲** — 目标是逼出具体案例和隐性判断标准，不是要方法论；
2. **案例库需求** — 每模块几个案例、覆盖哪些维度、从哪来；
3. **练习数据包清单** — 每个模块的练习需要什么输入材料，**脱敏规则是硬规则**：
   真实客户材料一律不得直接进课件，姓名 / 手机号 / 单号 / 精确金额全部替换为虚构等价数据；
4. **排期表** — 里程碑 × 交付物 × 责任人 × 日期。

模板与脱敏细则见 `references/content-dev.md`。

写入蓝图 `## 八、内容开发计划`。

---

## Phase 8：运营 / TTT / 路线图 / 待确认项【L 档】

**M 档跳过这一节**，直接进「生成交付包」。L 档（训练营 / 体系化项目）才需要：

| 小节 | 内容 |
|---|---|
| 九、平台运营与 TTT | 线上平台选型建议、学习社群运营节奏、内训师选材标准与认证路径（试讲 → 带教 → 独立开课） |
| 十、实施路线图 | 分期：试点班 → 修订 → 规模化，每期的时间、班次、覆盖人数 |
| 十一、待确认项 | **决定项目能不能落地的清单**：谁拍板、预算、场地、数据权限、业务方配合度 |

十一节不是走过场——把「还没确认的事」明明白白列出来，是这份蓝图最能体现专业度的地方。

写入蓝图 `## 九、…` `## 十、…` `## 十一、…`。

---

## 写入蓝图的方式

模板 `templates/course.blueprint.md` 把六节之后**注释掉**留作路线图：

```
<!-- 以下章节由 /course-delivery 补全（M / L 档）…
## 六、教学方法与互动设计
…
-->
```

**把整段注释删掉，换成真正的章节内容。** 保留在注释里 = `nextcourse check`
和 `nextcourse package` 都读不到（两者都会先剥掉注释再解析）。

一~五节是 `/course-design` 的地盘，除非用户明确要改，否则不要动。
**特别不要动第五节的模块清单表**——它是 `check` 与 `package` 的解析对象。

---

## 生成交付包

蓝图补完，按顺序跑：

```bash
nextcourse check <name>              # 先过闭环校验，error 必须清零
nextcourse package <name> --render   # 生成 package/*.md 并渲染 package/html/
```

`package` 会把蓝图六~八节的内容搬进对应交付文档；蓝图没写的地方会留
`> **待补**：…` 标记——**这些标记就是你的待办清单**，回到对应 Phase 补齐蓝图，
再重跑 `nextcourse package <name> --render --force`。

产出：

| 文件 | 谁看 |
|---|---|
| `package/facilitator-guide.md` | 讲师 —— 逐模块讲授要点、活动指令、幻灯片备注 |
| `package/workbook.md` | 学员 —— 练习、填写区、自检清单 |
| `package/assessment.md` | 项目方 —— L1 问卷、L2 考核、评估范围声明 |
| `package/rubric.md` | 讲师 —— 打分量规与汇总表 |
| `package/facilitation.md` | 讲师 / 助教 —— 时间轴、分组、积分规则 |
| `package/content-dev.md` | 项目组 —— SME 访谈、案例库、数据包、排期 |
| `package/action-plan.md` | 学员 —— 30 天承诺 + 30/60/90 复盘 |
| `package/alignment.md` | 内部 —— 对齐矩阵（由 `check` 生成） |
| `package/html/` | **客户** —— 上面这些的 HTML 版，双击即读、可打印 |

### md 是源，HTML 是交付物

和 `deck.html` 完全一样的心智模型：**HTML 永远不手改**，改 `package/*.md` 再重新
`--render`。已存在的 md 默认不会被覆盖（手改优先），要重新生成才加 `--force`。

### 打印验收（硬性，不是锦上添花）

交付包的 HTML 客户多半会导出 PDF 或直接打印。渲染完**必须**在 Chrome 打印预览里过一遍：

① 背景色 / 表头底色全部保留　② 每页边距一致、内容不贴边　③ 无空白页
④ 表格与活动卡无腰斩　⑤ 标题不落在页尾　⑥ 强制分页点生效　⑦ 导出 PDF 与预览一致

任何一条不过，改 `shared_styles/package-doc.css`，不要在单个 HTML 里打补丁。
需要在某处强制分页，在 md 里写 `<!-- pagebreak -->`；需要手写填空区写 `<!-- fill:3 -->`。

## 收尾提示

```
交付层已完成：
  设计蓝图   courses/<name>/course.blueprint.md   （六~十一节已补）
  交付包 md  courses/<name>/package/*.md          （源文件，改这里）
  客户交付物 courses/<name>/package/html/         （双击 index.html）

下一步：
  /slide-design <name>                     还没做幻灯片的话
  nextcourse export <name> --with-package  幻灯片 + 交付包一起打包给客户
```

同时把 `package/` 里剩下的 `> **待补**：` 条目念给用户听——那是这门课离「能开班」还差的东西。
