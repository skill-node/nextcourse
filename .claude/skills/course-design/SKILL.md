# /course-design — NextCourse 课程大纲设计 Skill

## 触发方式

```
/course-design
/course-design <主题关键词>
```

从零开始对话式地引导用户完成**课程定位 → 学习成果 → 知识架构**三个阶段，
最终输出 `courses/<name>/course.meta.md`，为 `/slide-design` 提供完整输入。

---

## 工作流总览

```
Phase 1: 定位      → 确认受众、情境、核心价值主张
Phase 2: 成果      → 用 Bloom 动词写 3-5 条可测量学习成果
Phase 3: 知识架构   → 拆分模块，确定每模块主题与页数
           ↓
     写 course.meta.md
           ↓
     提示用户运行 /slide-design <name> 进入渲染阶段
```

**在每个 Phase 内，先用 1-2 个问题引导用户，再给出建议，用户确认后才推进到下一阶段。不要一次输出所有内容让用户被动接受。**

---

## Phase 1：课程定位

### 引导对话（依次问，不要一次全问）

**问题 1：** 这门课程是给谁上的？（角色 + 经验水平 + 场景）

> 例："公司内部培训，面向刚入职 3 个月的销售人员" / "付费在线课，面向想转行数据分析的 28-35 岁职场人"

**问题 2：** 学员上完课之后，希望他们能做到一件具体的事是什么？

> 用"他们能够…"造句，越具体越好

### 根据用户回答，产出：

```
受众画像  : [1 句话描述]
核心情境  : [学员在什么场景下用这门课学到的东西]
价值主张  : [为什么他们要学这门课而不是别的]
```

让用户确认或修改后进入 Phase 2。

---

## Phase 2：学习成果设计

### 原则
- 使用 **Bloom 分类法动词**（从低到高：记住→理解→应用→分析→评估→创造）
- 每条成果必须**可测量**（能写出怎样的考题或实操任务）
- 3-5 条，不要超过 5 条（宁缺毋滥）
- 动词要多样化，至少覆盖 3 个 Bloom 层次

### Bloom 动词参考

| 层次   | 关键动词                                   |
|--------|-------------------------------------------|
| 记住   | 说出、列举、识别、定义                     |
| 理解   | 解释、总结、区分、举例                     |
| 应用   | 使用、执行、操作、完成、配置               |
| 分析   | 分解、对比、诊断、识别原因、判断           |
| 评估   | 评价、选择、验证、论证                     |
| 创造   | 设计、构建、规划、开发、生成               |

### 引导对话

**问：** 你希望学员在以下 3 个能力层次上各有什么收获？（可以只回答你觉得重要的）
- 他们需要**知道/理解**什么？
- 他们需要能**做到**什么？
- 他们能**创造/决策**什么？

根据用户回答，起草 3-5 条学习成果。每条包含三个字段：
- `do` — 动词开头的可观察行为（学完能做什么）
- `bloom` — 所属 Bloom 层级
- `success` — 成功标准（怎样算达成，能写出考题或实操验收）

```yaml
outcomes:
  - { do: "解释 X 的工作原理及适用边界", bloom: understand, success: "能用自己的话向同事讲清并举 1 个反例" }
  - { do: "使用 X 完成 Y 任务", bloom: apply, success: "独立完成 Y 并通过检查清单验收" }
  - { do: "诊断 X 场景中的 Y 问题", bloom: analyze, success: "对 3 个给定案例说出根因与对策" }
```

**质量闸门：** 若 3-5 条成果大多停留在 记住/理解 层，提醒用户"课程可能太浅"，建议至少 1 条达到 apply 及以上。让用户确认后进入 Phase 3。

---

## Phase 3：知识架构设计

### 原则
- 每个模块聚焦**一个核心主题**（用户离开时能说出这一句话）
- 典型结构：2-4 个模块，每模块 5-8 张幻灯片
- 总页数建议：15-30 张（60-90 分钟课程）
- 开头必须有：封面（1张）+ 课程概览（1张）
- 每个模块必须有：模块封面（1张）+ 内容页 + 模块总结或过渡（1张）
- 结尾必须有：学习路径 / 下一步（1张）+ 致谢/结束（1张）

### Merrill 第一原理（每模块内部结构参考）

```
Hook     → 为什么学员要在乎这件事？（问题 / 现实冲击）
Concept  → 核心知识点是什么？
Demo     → 真实案例 / 流程演示
Practice → 学员能练习什么？
Takeaway → 这个模块最重要的一句话是什么？
```

### 引导对话

**问：** 这门课的内容可以分成几个大块？每一块核心解决什么问题？

根据用户回答，产出模块拆分建议：

```
模块一：XXX（约 X 张）
  解决问题：...
  核心页面类型：Hook → Concept → Demo → Takeaway

模块二：XXX（约 X 张）
  解决问题：...
  核心页面类型：...
```

让用户确认总体架构。如果用户对某个模块有具体内容要求（某张页面要加什么），在这一步记录下来。

```markdown

outcomes:
  - { do: "动词开头的行为", bloom: apply, success: "成功标准" }
  - { do: "动词开头的行为", bloom: analyze, success: "成功标准" }
  - { do: "动词开头的行为", bloom: create, success: "成功标准" }
---

## 课程大纲

### 封面与概览（2 张）
- 封面页：标题 + 核心价值主张
- 课程概览：目标 + 大纲

### 模块一：XXX（X 张）
- Hook：...
- Concept：...
- Demo：...（具体案例内容）
- Takeaway：...

### 模块二：XXX（X 张）
- ...

### 收尾（2 张）
- 学习路径 / 下一步行动
- 致谢结束
```

### 题材域适配（贯穿三个 Phase 使用）

不同题材的教学形态差异很大。识别课程所属题材后，按此表调整引导重点、模块结构和 theme 推荐（用户可覆盖）：

| 题材 | 教学形态重点 | Practice 形式 | 推荐 theme |
|---|---|---|---|
| 领导力 / 软技能 | 案例讨论驱动：真实情境 → 多方视角 → 反思。Demo 页多用案例与金句，少用流程图 | 情境研讨、角色扮演、自评量表（不是"动手操作"） | `warm-sand` 或 `dark-botanical` |
| AI / 技术工具 | Demo 驱动：先看到效果再讲原理。每模块必须有可跟做的操作演示 | 动手任务 + 检查清单验收 | `bold-signal` |
| HR / 制度合规 | 场景判断驱动：对/错边界、政策条文 → 具体情境判断。多用对比和判断题 | 情景判断题、合规检查清单 | `standard-default` |
| 数据 / 分析 | 图表与数字驱动：结论先行，数据佐证 | 读图任务、指标计算 | `dark-ocean` |
| 创意 / 设计 | 视觉范例驱动：好坏对比、before/after | 点评练习、改稿任务 | `creative-voltage` |

其他风格补充：极简瑞士 `swiss-modern`（管理/战略）、手记粉彩 `notebook-tabs`（工作坊/互动）。全部 8 套见 AGENT.md 配色表。

**Phase 2 提示：** 领导力/合规类成果多落在 analyze/evaluate 层（判断与决策），技术类多落在 apply/create 层（操作与搭建）——如果起草的 Bloom 分布与题材惯性不符，向用户确认是否有意为之。
